# Spontaneous payment at a PSP

This process involves the spontaneous payment being executed at the infrastructures made available by the PSP, such as banks and ATMs, post offices and postal points, bars, newsstands, betting shops, supermarkets, tobacconists, and other affiliated merchants.

Typically, after entering the essential service data needed to define the debt position, the user can proceed with the payment.

<figure><img src="../../.gitbook/assets/Screenshot 2026-01-20 alle 12.28.38.png" alt=""><figcaption></figcaption></figure>

- The [demandPaymentNotice](../../appendix/Primitives/psp/soap-api.md#demandpaymentnotice) can be used by PSPs to send the specific service data entered by the user in order to receive the information to start the payment process in response; this step is mandatory for PSPs;
- the [paDemandPaymentNotice](../../appendix/Primitives/Creditor-Entity/api-soap.md#pademandpaymentnotice) is used to request the EC to create the debt position based on the specific service data sent; the EC will send the notice number and the Beneficiary Entity's data in response;
- with the [activatePaymentNotice](../../appendix/Primitives/psp/soap-api.md#activatepaymentnotice-1), the PSP asks the node to activate the payment with the EC, making sure to insert into the _qrCode_ tag what it received in the _response_ to the [demandPaymentNotice](../../appendix/Primitives/psp/soap-api.md#demandpaymentnotice), also in the _qrCode_ tag; this step is mandatory for PSPs;
- the payment activation request reaches the EC via the [paGetPayment](../../appendix/Primitives/Creditor-Entity/api-soap.md#pagetpayment), unless the EC can identify the debtor autonomously and correctly fill in the _debtor_ tag, it is possible to use dummy data (e.g. "ANONYMOUS");
- the PSP is required to provide the payment outcome **within 2 sec** with the [sendPaymentOutcome](../../appendix/Primitives/psp/soap-api.md#sendpaymentoutcome), both in case of a successful payment (outcome = OK) and a failed payment (outcome = KO);
- through the [paSendRT](../../appendix/Primitives/Creditor-Entity/api-soap.md#pasendrt) primitive, the _receipt_ (receipt) is forwarded to the _n_ ECs involved in the payment only if the payment was successful; the _receipt_ is an object generated by the pagoPA platform;
- when the EC receives the _receipt_, it must close the debt position and consider it fully paid.

For error handling, refer to [Error Handling](https://app.gitbook.com/o/KXYtsf32WSKm6ga638R3/s/mU2qgiLV1G3m9z1VjAOc/ "mention").
