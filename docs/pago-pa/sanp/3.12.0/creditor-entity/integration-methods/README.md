# Integration methods

PagoPA provides interested parties (i.e., Technological Intermediaries, Technological Partners, or Creditor Entities) with two methods for integrating with the pagoPA platform:

- [Integration via asynchronous APIs](integrazione-tramite-api-asincrone.md "mention")
- [Integration via synchronous APIs](integrazione-tramite-api-sincrone.md "mention")

Each interested party is free to choose the integration method that best suits its configuration. It remains understood that Technological Intermediaries, Technological Partners, or Creditor Entities using integration via synchronous APIs are required to submit all managed debit positions to the _Centralized Notice Archive_ (ACA).

The provision of these integration methods falls within the scope of obligations arising from the subjection under art. 146 of the T.U.B. of PagoPA to the supervision by the Bank of Italy to ensure the operational continuity measures to be adopted by payment system operators and critical providers of infrastructure or technical services for payment systems and related technological or network infrastructures.

On March 20, 2024, a communication was sent to Public Administration Creditor Entities and their Partners and/or Technological Intermediaries. In light of the above, it requests each Creditor Entity to evaluate the integration method it intends to adopt and, if necessary, contact its Partner and/or Technological Intermediary, so that they can send the relevant migration plan to PagoPA S.p.A. All existing contractual obligations between the Technological Partner and each Entity remain in force; therefore, the Partner and/or Intermediary assumes responsibility for the declaration. PagoPA S.p.A. will not be held liable for any activities resulting from this declaration.

For technical questions regarding the implementation of pagoPA, you can open an issue directly on GitHub [https://github.com/pagopa/pagopa-api/issues](https://github.com/pagopa/pagopa-api/issues)
