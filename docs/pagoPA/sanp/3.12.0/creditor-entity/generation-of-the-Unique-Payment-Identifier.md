# Generation of the Unique Payment Identifier

As defined in [paragraph 7.1 of the Guidelines](https://www.gazzettaufficiale.it/eli/id/2018/07/03/18A04494/sg):

> _"..., each Creditor Entity assigns an identification code called 'Unique Payment Identifier' (IUV) to each collection transaction, which cannot be associated over time with any other collection issued by the same Creditor Entity....."_

The IUV code therefore assumes fundamental importance

> _"... in order to enable payment reconciliation activities by Creditor Entities and fund transfers by Payment Service Providers... "_

therefore representing one of the essential elements on which the pagoPA system is based.

The same [paragraph 7.1 of the Guidelines](https://www.gazzettaufficiale.it/eli/id/2018/07/03/18A04494/sg) gives CEs the option to

> _".... delegate to a third party, in whole or in part, the generation of the Unique Payment Identifier, ensuring that its uniqueness is maintained over time"._

It follows that the generation of an IUV code that is **unique** over time is the responsibility of the CE, which must ensure during creation that the code complies with existing international specifications and the guidelines specified in the [SACI](https://docs.pagopa.it/saci).
